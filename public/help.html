Installation & backend

Comment utiliser DropQR.

Le site est maintenant séparé en plusieurs pages et un vrai backend Express gère les uploads, les téléchargements, les suppressions et l’expiration.

Pourquoi le QR code affiche “Missing Traffic Access Token” ?

La capture que tu as envoyée vient de la preview Arena/e2b. Cette preview protège l’URL avec un header nommé e2b-traffic-access-token. Quand tu scannes le QR code avec ton téléphone, l’appareil ouvre l’URL directement, mais il n’a pas ce header. La plateforme bloque donc la requête.

Conclusion : dans cette preview, le site fonctionne dans le navigateur Arena, mais le QR code ne peut pas être scanné librement depuis un appareil externe. Ce n’est pas un problème du backend DropQR. Pour un vrai test téléphone, utilise le réseau local ou déploie le site.

Tester entre ton PC et ton téléphone sur le même Wi-Fi

Lance le site avec une URL publique locale correspondant à l’IP de ton PC. Exemple :

cd file-transfer-site
npm install
PUBLIC_URL="http://192.168.1.25:3000" npm start

Ensuite, ouvre http://192.168.1.25:3000 depuis ton téléphone. Le QR code contiendra cette IP au lieu de localhost.

Il faut aussi que ton pare-feu autorise le port 3000.

Mettre le site en ligne

Tu peux le déployer sur un VPS, Railway, Render, Fly.io, etc. En production, utilise HTTPS et configure PUBLIC_URL avec ton domaine :

PUBLIC_URL="https://dropqr.ton-domaine.com" npm start

La limite de taille a été retirée côté application. Depuis la version 1.7.0, l’interface envoie aussi les fichiers par morceaux configurables pour éviter les blocages liés aux gros fichiers.

Après déploiement, vérifie /api/health. La réponse doit contenir version: 1.7.0 et chunkedUpload: true. Si ce n’est pas le cas, le frontend est à jour mais pas le backend.

Pourquoi Netlify affiche une 404 ?

Netlify Drag & Drop héberge surtout des fichiers statiques. Le ZIP complet contient un backend Node.js avec server.js, mais Netlify ne le lance pas en mode statique. Résultat : pas d’API, pas d’upload, et parfois une page “Page not found” si le mauvais dossier a été publié.

Pour DropQR complet, utilise Render, Railway, Fly.io ou un VPS. Si tu veux seulement afficher les pages statiques sur Netlify, publie le dossier public, mais l’envoi de fichiers ne fonctionnera pas.

Routes du backend

  • GET /api/health — santé du serveur.
  • GET /api/config — configuration publique et détection de preview Arena.
  • POST /api/transfers — upload classique d’un fichier.
  • POST /api/transfers/chunk — upload par morceaux configurables, utilisé par l’interface pour éviter les limites proxy/hébergeur liées aux gros fichiers.
  • GET /api/transfers/:id — statut public d’un transfert.
  • DELETE /api/transfers/:id — suppression manuelle avec la clé privée retournée à l’upload.
  • GET /t/:id — page de téléchargement.
  • GET /download/:id — téléchargement du fichier.

Le backend lance aussi un nettoyage automatique toutes les minutes pour supprimer les fichiers expirés.

Envoyer des vidéos

DropQR accepte aussi les vidéos. Quand le fichier reçu est une vidéo, la page /receive affiche un lecteur intégré pour la regarder dans le navigateur, avec un bouton pour télécharger le fichier original.

La lecture utilise /view/:id avec support des requêtes Range, ce qui permet d’avancer dans la vidéo sans télécharger tout le fichier.

Envoyer le code et le QR code sur Discord

DropQR peut poster automatiquement le code court et le QR code dans un salon Discord après chaque upload. Le plus simple est d’utiliser un webhook Discord : ça se comporte comme un bot pour poster des messages, sans avoir besoin d’un token de bot.

  1. Dans Discord, ouvre les paramètres du salon.
  2. Va dans Intégrations, puis Webhooks.
  3. Crée un webhook nommé DropQR et copie son URL.
  4. Ajoute l’URL dans les variables d’environnement de ton hébergeur.
DISCORD_WEBHOOK_URL=https://discord.com/api/webhooks/...
DISCORD_USERNAME=DropQR
# Optionnel : mention utilisateur ou rôle
# DISCORD_MENTION=<@123456789>
# DISCORD_MENTION=<@&123456789>

Après redéploiement, vérifie /api/health. La réponse doit contenir discordConfigured: true. Le message Discord sera supprimé automatiquement à l’expiration du transfert.

Et pour un vrai stockage robuste ?

Actuellement, DropQR stocke temporairement les fichiers sur le disque du serveur. C’est simple et rapide. Pour une version production à gros volume, je recommande Cloudflare R2, Backblaze B2 ou AWS S3 avec une règle de suppression automatique.

Je déconseille TeraBox pour ce rôle : ce n’est pas un backend applicatif stable de type S3, et les intégrations disponibles reposent souvent sur des scripts non officiels ou des cookies de session.

Si tu veux que je branche Cloudflare R2/S3, il faudra me fournir ces variables dans un fichier .env :

STORAGE_PROVIDER=r2
S3_ENDPOINT=https://xxxxxxxx.r2.cloudflarestorage.com
S3_BUCKET=nom-du-bucket
S3_ACCESS_KEY_ID=xxxxxxxx
S3_SECRET_ACCESS_KEY=xxxxxxxx
PUBLIC_URL=https://ton-domaine.com
